## TV 视频封装 APK 可行性分析（只读，未改代码）

结论：现有项目是通用 WebView 壳，不能直接满足 Android 5+ TV 视频需求，需改造；建议做独立 TV profile，避免影响默认产物。

关键发现（已逐行核验）：
- `server/engine/apk_builder.py:495` 使用 `InputStream.readAllBytes()`（Android API 33+），而 Manifest minSdk=21（`:1111`），异常被 `:509` 吞掉 → API 21–32 启动加载 `about:blank` 白屏。改 ByteArrayOutputStream 循环读取，是 Android 5 目标的首要修复。
- Manifest `:1121-1127` 只有 LAUNCHER，无 LEANBACK_LAUNCHER / leanback uses-feature / touchscreen required=false → TV 主屏不可见。
- `AppChromeClient`（`:623-680`）无 onShowCustomView/onHideCustomView；无 configChanges；`:407` 只解除自动播放手势限制，视频元素全屏不可用。
- 遥控器：全 server/ 无 dispatchKeyEvent / KEYCODE_DPAD / MediaSession；无字幕、无媒体键控制。
- 去广告：AD_HOSTS（`:263-299`）+ shouldInterceptRequest（`:352-394`）+ 弹窗拦截（`:646-650`）已有；但 `extra_ad_hosts` 只在 apk_builder 内消费，无生产者，因为 `distiller.py:439-461` `_feature_options` 是白名单。
- 跳转：`handleNavigation`（`:570-589`）对 http(s) 一律放行，无白名单。
- 注入挂载点：`_config_json()`（`:1800-1816`）→ assets/webtoapp_config.json → `loadConfig()`（`:491-511`）；`evaluateJavascript` 已有 blob 用法（`:810-830`），可在 onPageFinished 注入自定义 JS/CSS。
- 模板 `ACTIVITY_JAVA`+`MANIFEST_XML` 内容哈希自动失效缓存（`:1145-1150`），改模板无需手工删缓存。
- 测试仅字符串断言（tests/test_apk_template.py），CI 不装 Android SDK，无 API 21 真机/模拟器回归；签名无 apksigner verify。
- 限制：系统 WebView、无 ExoPlayer/DRM/HLS 保障；去第三方站点广告有 ToS 合规风险；无代理层（`/api/*` 代理永久 410）。

## 上机冒烟最终结果（提交 7963c78）

- 用户设备为 adb 连接的 Android 9 / API 28 手机（NE2211），不是模拟器。最初打不开网页的原因：本机 8000 服务未启动 + APK 写的是虚拟网卡 IP `10.204.181.136`，设备不可达。改用 `adb reverse tcp:8000 tcp:8000` + APK URL `http://127.0.0.1:8000/` 后页面正常加载。
- 关键结论：纯系统 WebView 的 `requestFullscreen()` 在无用户手势时被拒（logcat: "API can only be initiated by a user gesture"）；`webkitEnterFullscreen()`、`evaluateJavascript().click()`、Activity 内转发按键都不算手势。真实 DOM 点击（touch）可触发 `onShowCustomView`。
- 最终方案：注入默认聚焦的「全屏」按钮，遥控器 OK 在 `dispatchKeyEvent` 中转换为该按钮上的可信 `MotionEvent`（通过 `WebToApp.setFullscreenButtonRect` 上报坐标），一次按键进入系统 WebView 全屏；BACK 先退全屏。i18n/文案已改为 "Fullscreen on OK / OK 键全屏"。
- 实测通过：OK 进全屏、BACK 退全屏、字幕键弹出「关闭字幕/English/中文」且字幕渲染、页面加载、广告域名无干扰。`apksigner verify` v1/v2/v3 通过。
- 测试：定向 154 passed；完整 pytest 458 passed / 108 failed（同一沙箱 WinError 32）。
- 已清理：调试日志、`console.log`、测试页诊断按钮、所有截图与 classes.dex、8000 端口服务、adb reverse。保留：`generated/tv-smoke/` 下的 APK、site 素材与 `build_smoke_apk.py`（默认 URL 改为 127.0.0.1）。

## 修复：遥控器焦点到影片卡片 OK 不响应

- 根因：`dispatchKeyEvent` 的 ENTER 分支无条件向注入的“全屏”按钮坐标发可信 MotionEvent，从不调用 `__wtaTvActivate()`，所以焦点在卡片/链接上按 OK 实际点的是全屏按钮（首页无 video 直接 return）。
- 修复：Bridge 新增 `focusIsFsBtn` 状态（JS 通过 `setFocusIsFsBtn` + `focusin` 监听实时上报）；OK 仅当焦点在全屏按钮时发可信触摸，其余焦点元素走 `__wtaTvActivate()` → `el.click()`。
- 播放页兼容：Next.js 的 `<video>` 晚于 `onPageFinished` 渲染，TV_FULLSCREEN_JS 用 200ms 轮询（最多 30 次）等 video 出现后再 `btn.focus()`，确保播放页 OK 仍默认进全屏。注意：注入 JS 是单行拼接，禁止用 `//` 注释（曾导致后续代码被吃掉、`fsX=-1`）。
- 实测：首页电影卡片 OK 进入详情页（`百日谎言`）；“体育直播 >”链接 OK 正常导航；播放页 OK 进入系统全屏；全屏+焦点状态日志确认 `focusIsFsBtn` 切换正确。
- 测试：定向 156 passed（新增 `test_tv_ok_activates_focused_element_not_always_fullscreen` 与延迟聚焦断言）。最终 APK 已重建安装，v1/v2/v3 签名通过。

## TV 遥控器三项体验修复（按钮可见性 / 焦点 / 全屏按键）

- 问题1根因：站点悬浮的 home/主题按钮是无 `tabindex` 的 `<div>`（`.global-button-container ... cursor:pointer`），`focus()` 无效，遥控器永远到不了。修复：`TV_REMOTE_JS` 的 `candidates()` 纳入 `cursor:pointer` 的中小尺寸 div/span/li，`focusEl()` 在 `tabIndex<0` 时临时设 `tabindex=-1`。实测 DPAD 可聚焦主题按钮，OK 成功切换明暗主题。
- 问题2：`TV_FULLSCREEN_JS` / `TV_SUBTITLES_JS` 初始 `display:none`，300ms 轮询仅在存在 `<video>` 时显示全屏按钮；CC 按钮还要求 `v.textTracks.length===0`（WebView 已暴露字幕轨时隐藏 CC）。实测首页/详情页两按钮均隐藏，播放页仅显示全屏+CC（该站无 textTracks）。
- 问题3：进入系统全屏后 WebView 被移出视图树，按键仍发给 WebView。修复：`dispatchKeyEvent` 在 `customView!=null` 时走 `handleFullscreenKey()`——BACK 退出；DPAD_UP 聚焦原生“退出全屏”按钮，OK 点击它；DPAD_DOWN 聚焦播放器；DPAD_LEFT/RIGHT 快退/快进；媒体键与 OK 通过 `runFullscreenJsMedia()` 继续调 WebView JS `__wtaTvMedia()` 控制同一个 `<video>`（原生分发作兜底）；CAPTIONS 仍走字幕脚本。
- 附带修复：`onHideCustomView()` 把 `fullscreenContainer` 设为 GONE 后再次进全屏会黑屏；`onShowCustomView()` 现在显式 `setVisibility(VISIBLE)` 并 `bringToFront()` 退出按钮。实测退出后再次全屏正常。
- 注意：注入 JS 是单行字符串拼接，禁止 `//` 注释。测试定向 159 passed；APK v1/v2/v3 签名通过、minSdk 21、Leanback 入口。已清理所有调试截图与临时 HTML。

## TV 返回键 / 弹框 / 焦点三项修复

- 问题1（子页返回退出 APP）：新增 `isHomePage(url)`（path 为 `/` 或等于落地主页 path）与 `performBrowserBack(currentUrl)`。非主页时优先 `webView.goBack()`，无历史则 `loadUrl(config.url)` 回主页，绝不 `finish()`；仅主页才 `super.onBackPressed()`。BACK 在 `dispatchKeyEvent` 的 TV 分支里 DOWN/UP 都被消费（`return true`），系统不会再触发退出。
- 问题2（弹框返回关不掉）：新增独立 `TV_BACK_JS`（仅依赖 tvMode，不依赖 tvRemote），`__wtaTvBack()` 先找可见弹框（`[aria-modal]/[role=dialog]/[class*=modal|mask|popup]` 且 fixed/absolute z>=100、尺寸>180x120；再兜底扫描任意覆盖>50%视口的高 z 遮罩），点内部/全局关闭按钮（`closeLike` 判 aria-label/title/class 含 close 或文本 ×/关闭/取消，尺寸<90）并派发 Escape；无弹框才调 Bridge `performBack(location.href)`。Bridge 新增 `logBack`（Log.d `WebToAppTV BACK ...`）便于诊断。
- 问题3（首焦点+严格方向）：`TV_REMOTE_JS` 新增 `topLeft()`（行优先 `r.top*2+r.left` 最小；播放页 video 存在时优先全屏按钮）与 `resetFocus()`，注入时及 SPA URL 变化（`hrefKey=pathname+search`，popstate + 400ms 轮询）都重置到左上角，且 `focusEl(el,true)` 不滚动页面。`__wtaTvMoveFocus` 改为严格方向：只取 `main>8` 的元素，优先同行/同列（`cross<=tol`）的 `aligned` 池，取 main 最小、cross 次小；无对齐元素才退化到 loose 池，避免卡死。
- 实测：冷启动首页焦点在 logo；右键沿顶行到搜索图标；详情页下键到海报、右键到"剧情"标签；详情页 BACK 回到搜索结果页且 APP 未退出；本地可控 modal 页 BACK 日志 `modal-close` 且弹框消失、页面不动，page2 BACK 日志 `no-modal` 且回到 page1。真实站点登录弹框本次清数据后未复现，但检测逻辑覆盖其结构（白色居中卡片+暗遮罩+×）。
